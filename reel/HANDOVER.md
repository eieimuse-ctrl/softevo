# SoftEvo リール制作・運用ハンドオーバー（evolab）

この文書は「AI LEARNS TO WALK」シリーズの制作・運用の正本です。評価や経緯ではなく、確定したルールだけを書きます。迷ったらこの文書に従ってください。
Claude とのファイル受け渡しはすべて GitHub リポジトリ（eieimuse-ctrl/softevo）経由で行います。このファイルの正本は reel/HANDOVER.md です。

## 1. シリーズ概要
- アカウント：@softevolab（YouTube / TikTok / Instagram 共通）、表示名「evolab」
- 企画：ランダム生成のドット生物が、ニューラルネット＋遺伝的アルゴリズムで「移動」を自律的に獲得する過程を見せる英語圏向けショートシリーズ
- 1話16秒、縦型。視聴者はコメントで生物に名前をつけ、当選名は後の回で発表される

## 2. 動画フォーマット（確定仕様）
構成（固定）：
1. 冒頭フック：GEN 0 の失敗、または GEN 0／最終世代の上下比較（約1秒、脳パネルなし）
2. ニアミス：あと数 cm で届かなかった世代を山場にする
3. 達成：最終世代の成功＋距離・試行回数
4. 締め：FOLLOW ＋「Name it ↓」の名前募集、巻き戻しループ

技術仕様：
- 1080×1920、H.264、30fps、約16秒
- BGM あり（約 −14.5 LUFS）。最終世代の歩行リズムを BGM のビートに同期させる演出は意図的なもので、今後も維持する
- ナレーション（音声読み上げ）は入れない。物語は数字・プログレスバー・テロップで運ぶ

レイアウトの確定ルール（過去の検証で確定済み）：
- 脳パネルは画面高さの約28%でよい。縮小しない。パネルは画面下端まで伸ばし、下部の余白を作らない
- カードシーン（結果表示など）の文字は、生物がいた高さに置く（視線アンカー）。縦中央に寄せない
- 結果カードの数字カウントアップ演出は可

## 3. 制作ルール
- 型は固定し、変数は1本に1つだけ変える。変数の候補：地形（平地／階段／氷／谷間／坂道）、制約（筋肉の本数、頭の大きさ、脚なし等）、ゴール距離、移動方法の発見（歩行／転がり／…）
- 毎回「見える変化」を必ず入れる（YouTube の inauthentic content ポリシー対策：テンプレ量産と判定されると収益化対象外になり得る）
- 特別回は5〜7本に1回まで（全世代パレード、チャンピオン対決、視聴者設計の生物など）。パレードを本編の主構造にしない。使う場合は GOAL 後の2〜3秒の署名シーンとして、チャンピオンだけ色を付ける
- 投稿パッケージ形式（#001〜#003 と同一）：mp4（1080×1920）、cover.png、caption.txt、SPEC.txt（sha256 付き）。受け渡しは GitHub 経由。置き場所は非公開リポジトリ hsgwtest-lgtm/evolab-assets の packages/epNNN/（未公開動画を公開リポジトリに置かないため）。チャットに動画を直接送ると 720p に圧縮されるため、原本をチャットで送らない
- キャプション形式：物語3行（Gen 0…／ニアミス…／達成…🧬）＋「Random body, random brain. Nobody taught it how — just N tries of evolution.」＋「👇 Name this creature」＋ハッシュタグ #ai #evolution #neuralnetwork #machinelearning #simulation #pixelart

## 4. 投稿運用
- 最初の30日は毎日投稿：Day 1 = 2026-11-27（#001）〜 Day 30 = 2026-12-26（#030）、毎日 10:00 JST に3媒体同時
- TikTok / YouTube は Muse が事前予約する。Instagram は予約機能が使えないため、Muse が当日10:00に投稿する（ユーザーの承認タップが必要）
- YouTube タイトルの型：「AI LEARNS TO WALK #NNN — <世代数> Generations, <今回の変化>」。看板は WALK で統一し、回の変化は後半に書く（例 #003：動画内タイトルとカバーは「AI LEARNS TO ROLL」だが、投稿タイトルは「AI LEARNS TO WALK #003 — 172 Generations, It Rolled Instead」）

## 5. 名前発表ループ
- 各回のコメントから当選名を選出（集計は Muse 担当）
- 当選名は後の回の冒頭で発表する。#004 以降で開始

## 6. 展開フェーズ（市場調査 2026-11-26 に基づく決定）
- Phase 1（Day 1〜30）：毎日投稿、型は完全固定、30本までは数字で判断しない（Shorts のブレイク中央値は約71本、固定フォーマットの跳ね事例は32〜33日目）
- Phase 2（Day 31〜60）：週5本に落とし、3分長尺を開始（Day 35〜45 で1本目、設計パート＝体の設計判断とその結果を中心に。以後1〜2週に1本、Shorts から関連動画リンクで誘導）。特別回と視聴者設計の生物もここから
- Phase 3（Day 61〜90）：アプリ誘導は次の両条件を満たしてから。「英語版ゲームが開いて10秒で遊べる状態」＋「どれか1媒体でフォロワー1万人、または10万再生の動画」。それまではプロフィールにリンクを置かない

## 7. 計測（投稿ごと）
- 最後まで観た割合（目安70%以上）、平均再生率（75〜80%）、コメント率（0.5%以上）、フォロー転換（0.5%以上）、名前コメント数
- 冒頭の実験（上下比較フック等）は2秒離脱率で比較する。変更は1本に1つまで
- YouTube 公式のベンチマークは存在しないため、上記はクリエイター報告ベースの目安

## 8. 長尺（3分版）の設計方針
- 役割：ショートの完全版＋チャンネル登録への変換。再生数ではなく「ショートから来て登録した人数」で判定する
- 構成：最終形を冒頭3秒 → 体の設計（判断は3つだけ、各「判断→進化で起きた結果」とセット）→ 失敗モンタージュ → 脳の変化の深掘り1点 → ニアミス → 突破と最終走行 → 名前当選発表＋次回予告
- 設計の「考え方」は見せるが、パラメータの細かい調整値は見せない
- 締めは「あなたならどこを変える？」の設計募集。いいねの多い設計案を実際に作る回につなげる
